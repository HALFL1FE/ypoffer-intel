# 对话 Agent 文件上传与推广分析设计

日期：2026-09-11

状态：已按设计实现（2026-09-11）；真实浏览器拖拽和生产数据验收另行记录

配套计划：[实施计划](2026-09-11-agent-file-promotion-analysis.md)

## 1. 目标

用户在对话 Agent 上传商家清单，通过提问完成推广追踪页面上的分析：查看清单商家的推广前后表现、媒体贡献、链接表现和历史趋势，并在同一会话继续追问。

文件提供分析对象，推广追踪接口提供经营指标，Agent 负责理解问题和解释结果。相同清单、日期和筛选条件下，Agent 与推广追踪页面的数值必须一致。

第一版支持 XLSX、XLS、CSV、TSV 商家清单。PDF、图片、任意业务表格问答和多文件关联不在本期范围内。

## 2. 用户体验

### 2.1 主流程

1. 用户点击输入框旁的“上传清单”，或从系统文件夹把一个文件拖入输入区域。
2. 本机解析文件，展示文件名、有效商家数、合并重复数量、跳过行数量，以及商家预览。
3. 用户确认清单。仅询问文件内容时可直接发送；查询经营指标前，需要确认推送日期和分析窗口。
4. 用户提问，例如：“分析这批商家推送后一周的表现，找出增长最多的商家。”
5. Agent 查询这批商家的推广追踪数据，展示结果卡片并生成解释。
6. 用户继续问“哪些媒体贡献最大？”或“第二个商家过去几个月表现如何？”，沿用当前清单；日期和商家范围变化时显示本次实际条件。

示例中的推送日期由用户指定，系统不把示例日期或今天自动当成推送日期。

### 2.2 上传区域

- 保留现有文本输入框、发送和停止按钮，增加上传按钮、拖入高亮和附件卡片。
- 附件卡片显示：文件名、商家数、当前日期条件、“查看清单”“替换”“移除”。
- 同时只保留一个有效附件。替换文件解析失败时，保留原附件。
- 拖入多个文件、文件夹或不支持的格式时，明确提示支持范围。拖入文件时阻止浏览器导航打开文件；普通文本拖拽不受影响。
- 解析中和回答生成中禁用附件替换、移除及日期修改；停止当前回答后可修改。
- 页面提示：“文件在本机解析，分析所需的清单信息会随提问发送。”

第一版建议文件大小上限为 **5 MiB**；这是新增产品限制。商家上限 **200 个**、分析窗口 **1–92 天**沿用现有推广追踪限制。

### 2.3 日期处理

现有清单解析器不读取推送日期。第一版通过日期控件录入；问题中明确、完整的日期可以生成待确认候选值。缺少年份、时间范围含糊或与当前日期条件冲突时，先确认，再查询。

推送日期确认后，默认分析窗口为推送当天至第 7 天，比较窗口为紧邻其前的等长时间段。用户可调整分析开始、结束日期；实际窗口统一由现有 `windowDates()` 计算。每次回答展示实际分析窗口和比较窗口。

仅询问“文件里有哪些商家”“按文件中的品类统计数量”不要求日期，也不访问经营数据库。

## 4. 文件与会话模型

### 4.1 文件解析

共享读取层只负责将文件转成工作表二维数组。继续使用现有电子表格读取器和 CSV/TSV 解析器，不引入第二套表格库。

商家解析继续使用 `parseBatch()` 的规则：Merchant ID 与 Merchant Name 必填，品类、ASIN 可选，跨工作表按 Merchant ID 合并，上限 200 个商家。名称用于显示，ID 用于查询，不按名称模糊替换商家。

增加解析诊断：有效商家数、重复合并行数、无效 ID 行数、缺少名称的商家。现有无效 ID 跳过行为需要在预览中可见；缺失必填信息或没有有效商家时不接受附件。现有备注提取 ASIN 的能力保留，备注文本不进入模型指令。

### 4.2 新增上下文

新增只驻留当前页面进程的附件状态，由 Agent 页面工厂创建并注入主运行链路和降级组件。每次发送时生成不可变快照。

```ts
type PromotionWindow = {
  launchDate: string;
  startDate: string;
  endDate: string;
};

type PromotionManifest = {
  attachmentId: string;
  fileName: string;
  merchantCount: number;
  merchants: { merchantId: string; merchantName: string }[];
  window: PromotionWindow | null;
};

type AgentPromotionAttachment = {
  manifest: PromotionManifest;
  offers: TrackedOffer[];
};
```

`TrackedOffer` 复用推广追踪已有类型。文件二进制和工作表二维数组解析完成后释放；完整标准化清单留在浏览器。规划请求仅携带白名单摘要 `PromotionManifest`；具体文件事实通过工具结果按需返回。

附件 ID 在替换文件时重新生成；改变日期创建新的运行快照。工具执行必须匹配本次快照，不能读取某个后来被替换的全局附件。

### 4.3 生命周期

- 同一会话中的连续追问和页面内导航保留附件。
- 新建会话、退出登录、整页刷新清除附件及其报告缓存；刷新后提示重新上传。
- 移除附件后，新问题不再使用该清单。旧消息仍可展示已生成的分析，但不代表文件仍可查询。
- 切换附件、日期或筛选条件后，不复用不匹配的报告。缓存仅在同一次运行内复用，追问重新读取接口数据。
- 清单默认不写入推广追踪页面的本地批次列表，不生成持久化上传记录。

## 5. 新增工具 `promotion_analysis`

一个工具覆盖文件事实和推广分析，避免每个商家分别调用工具。无附件时不启用该工具。

### 5.1 参数

```ts
type PromotionToolArguments = {
  attachmentId: string;
  view: "file" | "merchants" | "merchant_media" | "publishers" | "links" | "history" | "categories";
  merchantIds: string[];
  window: PromotionWindow | null;
  metric: "revenue" | "clicks" | "dpv" | "atc" | "orders" | "commission";
  sortBy: "after" | "before" | "delta" | "change";
  direction: "asc" | "desc";
  offset: number;
  limit: number;
};
```

默认使用清单全部商家、销售额、分析期数值降序、`offset=0`、`limit=25`。文件视图忽略经营指标排序，按 Merchant ID 稳定排序；历史视图按月份升序输出所选指标。品类视图以文件品类分组，缺失项显示“未分类”。

规划器可以选择清单内商家子集；不能增加清单外 ID。所有经营数据视图必须提供已确认窗口。服务端先补全、校验参数，再签发调用证明；最终签名参数包括附件 ID、商家范围和日期。

### 5.2 数据读取与聚合

| 视图 | 数据来源 | 输出 |
| --- | --- | --- |
| `file` | 本机标准化清单 | 商家、文件品类、文件 ASIN，以及清单数量 |
| `merchants` | `loadReport()` 普通请求 | 商家前后指标、差额、变化率和排名 |
| `merchant_media` | `loadReport({ action: "relations", ... })` 的 `media` | 每个商家识别到的活跃媒体数量和排名 |
| `categories` | 普通请求 + 文件品类 | 按文件品类汇总的前后指标 |
| `history` | 普通请求的 `monthly` | 所选商家的历史完整自然月指标与基线 |
| `publishers` | `loadReport({ action: "relations", ... })` | 当前商家集合内按媒体汇总的前后指标 |
| `links` | 同一关系查询的 `links` | 商家、媒体、链接类型、目标 ASIN、成交 ASIN及指标 |

现有关系查询按期间聚合，不提供历史月份和每日序列；历史分析必须使用普通查询。单次运行按规范化请求参数复用查询，对同一商家集合及窗口，普通报告和关系报告各最多读取一次，不按 200 个商家逐一发送请求。

汇总、差额、变化率、排序和分页在确定性代码中完成，再交给模型解释。分页前计算总体指标，返回总行数、已返回数量和下一页位置。排名覆盖符合筛选条件的全部行，不把第一页当成完整样本。

商家总额来自商家报告；媒体总额只聚合媒体行。`merchant_media` 按商家统计有前后任一周期活动的非空媒体 ID，排除 `0`，同一商家内重复媒体只计一次。媒体行和链接行不能相加形成总额。媒体跨商家合并时以媒体 ID 为键，链接保留接口给出的商家、媒体及 ASIN 维度。

### 5.3 必须保留的业务语义

- 缺失或不支持的指标保持 `null`；不显示为 0，不参与伪造增长率。
- 基期小于等于 0、指标缺失或期间未完整覆盖时，不生成常规百分比增长结论。
- 历史基线只使用已有接口提供的完整自然月，不用当月未结束数据冒充整月。
- 文件 ASIN 是清单信息，不会自动把商家全部成交限制为这些 ASIN。需要商品级推广分析时，从链接结果区分推广目标与成交商品。
- 目标 ASIN 缺失时显示“未提供目标 ASIN”；成交 ASIN 单独展示。例如成交 `B0H2JJBFYX` 不足以反推推广目标。
- 数据体现所选商家在窗口内的表现，不证明某次邮件或推送带来了这些成交。回答使用“推送后观察到”，不声称“由本次推送带来”。

## 6. Agent 协议与回答

### 6.1 两条运行链路同时接通

`AgentRunRequest`、`AgentSessionRequest` 和 `AgentToolExecutionRequest` 增加可选附件快照；旧的无附件调用保持有效。

- 主运行链路：`CopilotKitAgentRuntime.vue` 将摘要放入 `offerIntelligence.promotionContext`；`agent_agui.py` 在初次规划、工具续跑、重规划和回答合成中保留它。
- 降级运行链路：`agentSession.ts` 向共享规划接口传摘要，工具读取本次附件快照。`CopilotKitAgentHost.vue` 降级重试必须沿用原请求。
- 页面工厂的异步组件加载失败分支也注入同一附件状态和读取器。
- 没有有效运行快照的工具调用拒绝执行；不能读取上一次会话的清单。

共享 Python 契约接受可选 `promotionContext`，继续使用现有 `v2` 请求结构和调用证明机制。摘要是用户数据，不能作为系统指令。调用证明约束请求与参数的一致性，不构成对客户端数据真实性的数据库认证。

### 6.2 有界工具结果

为新工具定义独立的扁平结果投影和验证器，建议采用与现有大结果工具同级的 **18,000 字节**上限，每页最多 25 行。保留六个指标的数值字段及 `null`，不直接把嵌套的完整 `PerformanceReport` 传给模型。

结果包含文件名、视图、实际日期、总行数、分页信息、总体指标、当前行和证据来源。经营报告保留 `availableThrough`、`generatedAt`、`supported`、`clickSource`；数据更新时间不等于完整性保证。

文件事实使用 `evidenceOrigin="file"`，现有外层 `source="unknown"`，并在卡片明确显示“上传清单”；数据库结果使用 `evidenceOrigin="database"` 和 `source="database"`。不把上传文件误标成数据库事实，也不扩展所有旧工具的数据源枚举。

完整请求继续服从当前规划 64 KiB、合成与 AG-UI 128 KiB 的限制。序列化后测量实际字节数；超预算时减少明细行并更新分页标识，不能截断 JSON、丢弃调用证明或悄悄截掉商家范围。摘要本身超预算时拒绝发送并提示缩短商家名称或拆分清单。

### 6.3 回答结构

默认回答按“结论 → 关键数值 → 商家或媒体明细 → 数据限制”组织，展示文件名、商家范围、实际窗口和数据截至日期。沿用现有指标、表格、摘要和趋势卡片；表格不超过已有的 8 个值列，多个指标按卡片拆分。

附件相关问题必须调用 `promotion_analysis` 获取证据，不绕到忽略清单范围的全局商家分析。历史消息可用于理解“第二个”“这些商家”等指代，但本次查询范围必须重新校验。首次规划不可用时最多受控重试一次；主链路与降级链路统一使用 `legacyParity` 回退字段，避免旧字段导致回退分支未触发。

模型不可用但数据库查询成功时，保留已验证的结果卡片并提示解释生成失败；不能用没有来源的自然语言替代结果。

## 7. 数据保护与失败处理

- 文件仅作数据输入。单元格中的命令、角色声明、链接和公式文本不提升为指令，不执行宏，不跟随外部链接取数。
- 复用现有登录和页面权限；前端不持有数据库令牌，服务端继续逐请求鉴权。新增工具不扩展用户权限。
- 不把文件二进制、完整工作表或完整解析清单写入结构化会话记忆、Trace 或诊断字段。保持原问题文本，不把清单拼进问题以规避契约。
- 现有用户主动导出的对话诊断可能包含已显示的回答内容；界面应说明这一点。附件相关诊断回放需要重新上传清单，且读取的是回放时的数据库数据。

| 场景 | 行为 |
| --- | --- |
| 不支持格式、文件过大、读取失败 | 显示具体原因，保留已有有效附件 |
| 必填列缺失、无有效商家、超过 200 个商家 | 阻止确认，指出需要修改的内容 |
| 推送日期缺失或存在冲突 | 保留问题，确认日期后再发送分析请求 |
| 无数据或指标不支持 | 展示无数据或不可用，不生成虚构的零值 |
| 401、403、数据库不可用 | 沿用登录、权限和错误提示；不改用无关缓存冒充同口径报告 |
| 关系结果超过接口限制 | 提示缩短日期窗口或选择更少商家 |
| 用户停止、离开页面或新建会话 | 取消本次请求，丢弃迟到结果，避免写入新会话 |

## 8. 验收标准

1. 选择文件和从系统文件夹拖入文件均可完成导入；文件夹、多文件和不支持格式均有反馈。
2. 四种格式遵循相同商家解析规则；重复合并、无效行和必填信息缺失可在预览中辨认。
3. 文件内容问题不访问数据库；经营问题缺少日期时先确认。
4. 同一测试清单及窗口下，Agent 与推广追踪页面的商家、媒体、链接和历史指标一致。
5. 排名、空值、零基期、未完整期间、重复媒体、目标与成交 ASIN 分离均有固定数据测试。
6. “继续看媒体”“只看某商家”“下一页”沿用正确附件与条件；替换、移除和新会话不会串用数据。
7. 主运行、降级运行、异步组件加载失败回退均支持附件；无附件对话维持原有行为。
8. 参数篡改、清单外商家、过期附件和超预算请求被明确拒绝；文件内容不能改变工具权限或系统指令。
9. 自动化回归、构建、真实浏览器验收分别记录。系统文件夹拖拽需要真实操作验证，合成拖放事件不单独作为通过证据。
